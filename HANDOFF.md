## What didn't work
- Initial PR #1 was opened on a branch that had 11 unrelated upstream commits — the PR diff was 15 files instead of 2. Fixed by `git rebase --onto origin/main` + force-push. Lesson: when creating a new branch from the local `main` reference, always verify `origin/main` matches first.
- First test for `Runtime.__repr__` used `assert "context=Context(user_id='u-1')" in text` — too tight, failed because the dataclass repr includes the qualified function-local class name (`test_runtime_repr.<locals>.Context(user_id='u-1')`). Fixed by matching the value part only.
- `Runtime.__repr__` initially used `drain_requested={self.drain_requested}` instead of nesting `RunControl.__repr__` — but the nested repr surfaces the actual drain reason, which is more useful. Updated design.
- Initial pass at `add_node` cleanup used `coerce_to_runnable(action, name=node, ...)` — but that doesn't tell the user what was wrong. Improved the bare `raise RuntimeError` to surface a descriptive message instead.
- PR #8 first edit accidentally deleted the `def test_untracked_value() -> None:` line while inserting the new tests. Restored in a follow-up edit. Lesson: when inserting before an existing test, anchor on the test body (or the prior test's `assert`) rather than the `def` line of the test being preserved.
- PR #8 consult initially proposed `except TypeError:` (the 4-model minority). - First consult prompt for PR #8 said `decimal.Decimal()` raises `ValueError` — incorrect, it returns `Decimal("0")` or raises `decimal.InvalidOperation` (an `ArithmeticError`). Did not affect the final decision because the Pydantic test was the real tiebreaker, not the decimal example.
